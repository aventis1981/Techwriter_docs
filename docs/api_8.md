# API: Частичное обновление объекта  (`PATCH /objects/{id}`)

Ресурс для частичного обновления объекта.
Метод может быть идемпотентным в текущей реализации API: повторная отправка идентичного запроса не приводит к дополнительным изменениям. 
Однако семантика HTTP не гарантирует идемпотентность PATCH — поведение зависит от логики сервера.

---

> **Важно:** Базовый URL вынесен в Postman-Environment как переменная `{{base_url}}`.  
> Пример значения: `https://api.restful-api.dev`.


## Описание запроса

| Параметр | Значение |
| --- | --- |
| **Метод** | `PATCH` |
| **URL** | `{{base_url}}/objects/{id}`|
| **Аутентификация** | Не требуется |
| **Accept** | `application/json` |
| **Content-Type** | `application/json` |
| **Формат ответа** | JSON с обновленными данными объекта |

>Content-Type указывает формат тела запроса; Accept — ожидаемый формат ответа. 

В Postman использовать: {{base_url}}/objects/{{id}}
где {{id}} — уникальный идентификатор объекта, существующего в системе (переменная окружения или коллекции)
---

### Примеры запросов

#### cURL

```bash
curl -X PATCH https://api.restful-api.dev/objects/1 \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "title": "only title updated"
    }
  }'
```

#### JSON

```jsonc
{            
  "data": {                          
    "title": "only title updated"                          
  }
}
```

|Поле	|Тип	|Обязательность	|Примечания|
| --- | --- | --- | --- |
|name	|string|нет |  Ярлык/имя объекта для поиска, фильтрации и отображения в списках. | 
|data| object или null | нет | Контейнер с произвольными полями объекта. Отсутствие поля data в запросе означает, что сервер не должен изменять существующее значение data. | 
|`data.*`| varies | нет| Произвольные вложенные поля объекта |

>Важно: PATCH выполняет слияние на верхнем уровне объекта. Если поле data передано, оно заменяется целиком — поля внутри data, не указанные в запросе, удаляются. 
>Для обновления отдельного поля внутри data нужно передать весь объект data со всеми нужными полями.
>*Пример:* обновление объекта, у которого внутри поля `data` есть поля `title1` и `title2`.
>Если нужно обновить только поле `title1`, в PATCH запросе  следует передать и `title1`, и `title2`.
>Если в PATCH передать только `title1`, то поле `title2` будет удалено.


### Примеры допустимых значений для вложенных полей (`data.*`)
`data` — контейнер с произвольными полями. Вложенные поля (data.*) могут иметь любой тип и набор ключей. 
Сервер не валидирует структуру внутри data.
- `"red"`
- `123`
- `true`
- `{"nested": "value"}`

## Коды ответов и поведение
|Код	|Статус	|Поведение API	|Что документировать для разработчика|
| --- | --- | --- | --- |
|200 |OK	|Успех	|Возвращает JSON с обновленными данными объекта |	
|400 |Bad request	|Ошибка в запросе	|Возвращает  "error": "Invalid request body" |	
|404 | Not Found |	Объект не найден |Возвращает  "error": "The Object with id = 9999999 doesn't exist. Please provide an object id which exists or generate a new Object using POST request and capture the id of it to use it as part of PATCH request after that." |


## Формат успешного ответа (200 OK)
Пример ответа для объекта с id=ff808181a09d98f701a0e8e0d40736b3:
```json
{
    "id": "1",
    "name": "name-updated",
    "updatedAt": 1790676334420,
    "data": {
        "title": "only title updated"
    }
}
```
## Пример ответа при ошибке 400 (Bad Request)
Если в теле запроса некорректный JSON или нарушена структура, сервер вернёт:
```json
{
  "error": "Invalid request body"
}
```
>Важно: При ошибке 400 сервер не возвращает детали о том, какое именно поле невалидно (например, «поле name слишком длинное»). 
>Клиент получает только общее сообщение Invalid request body. Для отладки рекомендуется проверять валидность JSON до отправки запроса.

## Структура ключевых полей
|Поле	|Тип	|Описание	|Ограничения / примечания|
| --- | --- | --- | --- |
|id|	string	|Уникальный идентификатор объекта	| id объекта согласно запросу|
|name	|string|	Ярлык/имя объекта для поиска, фильтрации и отображения| |
|data| object или null | Контейнер с произвольными полями объекта | Поля согласно запросу |
|`data.*`| varies | Произвольные вложенные поля объекта | Поля согласно запросу |
|updatedAt | number | Метка времени обновления | Возвращается сервером при PUT/PATCH |


## Ограничения и особенности (демо-API)

- Поле `id` всегда возвращается как строка (в кавычках): это может быть число в виде строки ("1") или UUID-строка ("ff808181...").
- Данные могут сбрасываться при перезапуске сервиса.

## Связанные эндпоинты

- `GET /objects` — получить список объектов.
- `GET /objects/{id}` — получить один объект по id.
- `GET /objects?id=...` — получить объекты по заданным параметрам.
- `POST /objects` — создать объект.
- `PUT /objects/{id}` — обновить объект полностью.
- `DELETE /objects/{id}` — удалить объект.
