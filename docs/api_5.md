# API: Получение объекта  (`GET /objects?id=...`)

Ресурс для получения одного или нескольких объектов из списка.

---

> **Важно:** Базовый URL вынесен в Postman-Environment как переменная `{{base_url}}`.  
> Пример значения: `https://api.restful-api.dev`.

## Описание запроса

| Параметр | Значение |
| --- | --- |
| **Метод** | `GET` |
| **URL** | `{{base_url}}/objects?id={id}`|
| **Аутентификация** | Не требуется |
| **Accept** | `application/json` |
| **Формат ответа** | JSON с данными объекта/объектов |


Можно запросить данные одного или одновременно нескольких объектов.
Запрос для одного объекта:

| Кол-во объектов | Параметр | Значение |
| --- | --- | --- |
| 1 объект | **URL** | `{{base_url}}/objects?id={id}` |   
| 2 объекта | **URL** | `{{base_url}}/objects?id={id1}&id={id2}` |   
| 3 объекта | **URL** | `{{base_url}}/objects?id={id1}&id={id2}&id={id3}` |   

---

### Примеры запросов

#### cURL

Запрос для одного объекта (id=1):
```bash
curl -X GET https://api.restful-api.dev/objects?id=1
```

Запрос для 2 объектов (id=1, id=ff808181a09d98f701a0ce34e2487b39):
```bash
curl -X GET https://api.restful-api.dev/objects?id=1&id=ff808181a09d98f701a0ce34e2487b39
```


## Коды ответов и поведение
|Код	|Статус	|Поведение API	|Что документировать для разработчика|
| --- | --- | --- | --- |
|200 |OK	|Успех	|Возвращает JSON с данными объектов.  В случае, если id объекта не найден, сервис возвращает пустой массив. |	

## Формат успешного ответа (200 OK)
Пример ответа для запроса двух объектов:
```json
[
    {
        "id": "1",
        "name": "Google Pixel 6 Pro",
        "data": {
            "color": "Cloudy White",
            "capacity": "128 GB"
        }
    },
    {
        "id": "ff808181a09d98f701a0ce34e2487b39",
        "name": "name",
        "data": {
            "title": "new object2",
            "body": "this is a text for object's body2",
            "userId": 2
        }
    }
]
```

## Структура ключевых полей
|Поле	|Тип	|Описание	|Ограничения / примечания|
| --- | --- | --- | --- |
|id|	string	|Уникальный идентификатор объекта	|Генерируется  системой|
|name	|string|	Ярлык/имя объекта для поиска, фильтрации и отображения в списках | |
|data| object или null | Контейнер с произвольными полями объекта | Структура не стандартизирована; может быть null |
|`data.*`| varies | Произвольные вложенные поля объекта | Любые ключи внутри data допустимы; набор полей зависит от объекта |

Содержимое data зависит от объекта: сервер не валидирует структуру внутри data. В списке могут встречаться объекты 
с разными наборами полей (например, `color` и `capacity` для телефонов, `price` для товаров) или с `data: null`.

## Ограничения и особенности (демо-API)

- ID передаётся через query-параметр id. Для запроса нескольких объектов параметр повторяется: `?id=1&id=2`.
- Поле `id` всегда возвращается как строка (в кавычках): это может быть число в виде строки ("1") или UUID-строка ("ff808181...").
- Ответ всегда приходит в виде массива, даже если запрошен один объект.
- Если ни один из запрошенных ID не найден — возвращается 200 OK с пустым массивом [].
- Данные могут сбрасываться при перезапуске сервиса.
- В случае, если часть из запрошенных объектов существует, а другая часть - нет, сервис вернет в ответе только существующие объекты, со статусом 200 ОК.
- Запрос данных объектов возможен также через path параметр `/objects/1` *(будет описан отдельно и добавлена ссылка)*.

## Связанные эндпоинты

- `GET /objects` — получить список объектов.
- `POST /objects` — создать объект.
- `PUT /objects/{id}` — обновить объект.
- `DELETE /objects/{id}` — удалить объект.
