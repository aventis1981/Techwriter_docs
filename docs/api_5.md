# API: Получение списка объектов (`GET/objects`)

Ресурс для получения списка объектов.

---

> **Важно:** Базовый URL вынесен в Postman-Environment как переменная `{{base_url}}`.  
> Пример значения: `https://api.restful-api.dev`.

## Описание запроса

| Параметр | Значение |
| --- | --- |
| **Метод** | `GET` |
| **URL** | `{{base_url}}/objects`|
| **Аутентификация** | Не требуется |
| **Тип контента (Content-Type)** | `application/json` |
| **Формат ответа** | JSON со списком объектов |

---

### Примеры запросов

#### cURL

```bash
curl -X GET https://api.restful-api.dev/objects
```

## Коды ответов и поведение
|Код	|Статус	|Поведение API	|Что документировать для разработчика|
| --- | --- | --- | --- |
|200 |OK	|Успех	|Возвращает JSON с данными объектов |	

## Формат успешного ответа (200 OK)
Это пример объектов из массива.
```json
[
  {
    "id": "1",
    "name": "Google Pixel 6 Pro",
    "data": {
      "color": "Cloudy White",
      "capacity": "128 GB"
    }
  },
  {
    "id": "2",
    "name": "Apple iPhone 12 Mini, 256GB, Blue",
    "data": null
  }
]
```

## Структура ключевых полей
|Поле	|Тип	|Описание	|Ограничения / примечания|
| --- | --- | --- | --- |
|id|	string	|Уникальный идентификатор объекта	|Генерируется  системой|
|name	|string|	Ярлык/имя объекта для поиска, фильтрации и отображения в списках | |
|data| object или null | Контейнер с произвольными полями объекта | Структура не стандартизирована; может быть null |
|`data.*`| varies | Произвольные вложенные поля объекта | Любые ключи внутри data допустимы; набор полей зависит от объекта |

Содержимое data зависит от объекта: сервер не валидирует структуру внутри data. В списке могут встречаться объекты 
с разными наборами полей (например, `color` и `capacity` для телефонов, `price` для товаров) или с `data`: null.

## Ограничения и особенности (демо-API)

- В списке встречаются предзагруженные объекты с `data`: null — создать такие через POST нельзя.
- Поле `id` всегда возвращается как строка (в кавычках): это может быть число в виде строки ("1") или UUID-строка ("ff808181...").
- Нет пагинации: `GET /objects` возвращает весь список одним ответом. При большом количестве объектов ответ может стать очень большим — 
в реальных системах для этого используют пагинацию, сортировку и фильтрацию.

## Связанные эндпоинты

- `POST /objects` — создать объект.
- `PUT /objects/{id}` — обновить объект.
- `DELETE /objects/{id}` — удалить объект.
- `GET /users` — проверить существование `userId` перед созданием объекта.
