# Шпаргалка по Git для работы с документацией (MkDocs)

## Быстрый цикл «правка → коммит»

|Команда|	Что делает	|
| --- | --- |  
|`git status -s`     |          Посмотреть, что изменилось и что уже staged|
|`git add .`     |          Добавить все измененные и новые файлы |
|`git add mkdocs.yml`  |          Добавить изменённый конфиг|
|`git add docs/api_8.md`   |     Добавить новый файл документации|
|`git diff --staged`      |        Проверить, что именно уйдёт в коммит|
|`git commit -m "feat: document PATCH /objects/{id} with shallow merge note"`| Закоммитить проиндексированный файл с комментарием |
|`git commit -am "new data added"`| Добавить и закоммитить измененный файл с комментарием  (только для измененных файлов, новые не добавит!|
|`git push`| Отправить файл в репозиторий|

>Важно: не использовать `git add .` в корне проекта — папка site/ генерируется автоматически и не должна попадать в репозиторий.


##Статус и staged-файлы
|Команда|	Что делает	|На что смотреть в выводе|
| --- | --- | --- |   
|`git status -s`	|Краткий статус	|M в 1-й колонке = staged; пробел + M = не staged; ?? = untracked|
|`git diff --staged`	|Показать изменения, готовые к коммиту|	Видишь diff → есть staged-изменения; пусто → staged пуст|
|`git ls-files --cached`	|Список файлов в индексе|	Просто список файлов, которые сейчас staged|

###Расшифровка статусов (git status -s)
`M  file.md` — файл изменён и уже в индексе (staged)
`M file.md` — файл изменён, но ещё не в индексе
`?? file.md` — файл не отслеживается (untracked), Git о нём не знает
`D  file.md` — файл помечен на удаление из репозитория

##Частые операции
| Задача	| Команда	| Важное примечание| 
| --- | --- | --- | 
| Добавить только изменённые (не новые)	| `git add -u`	| Новые файлы не трогает| 
| Добавить конкретный файл	| `git add <путь>`	| Точно контролируешь, что попадает в коммит| 
| Убрать файл из staged (оставить изменения)	| `git restore --staged <путь>`	| Например, если случайно добавил лишнее| 
| Закоммитить изменённые файлы + сообщение	| `git commit -am "msg"`	| -a не добавляет новые (untracked) файлы!| 
| Посмотреть историю коммитов| `git log --oneline`	| Удобно для проверки своих последних коммитов| 

##Нюансы для документации API
- Новые .md файлы (например, docs/api_9.md) нужно добавлять явно через git add. git commit -a их не увидит.
- Точность примеров: перед коммитом проверяй `git diff --staged`, чтобы не закоммитить обрезанные JSON-- примеры или опечатки в примерах cURL.
- Конфигурация MkDocs: изменения в `mkdocs.yml` лучше коммитить отдельно от правок в .md, чтобы было проще откатывать.
