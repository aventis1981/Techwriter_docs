# API: Создание нового объекта (`POST /objects`)

Ресурс для создания нового объекта.

---

> **Важно:** Базовый URL вынесен в Postman-Environment как переменная `{{base_url}}`.  
> Пример значения: `https://api.restful-api.dev`.

## Описание запроса

| Параметр | Значение |
| --- | --- |
| **Метод** | `POST` |
| **URL** | `{{base_url}}/objects`|
| **Аутентификация** | Не требуется |
| **Тип контента (Content-Type)** | `application/json` |
| **Формат ответа** | JSON с новым объектом |

---

## Параметры запроса

| Поле | Тип | Обязательность | Примечания |
| --- | --- | --- | --- |
| `name` | string | Нет | Ярлык/имя объекта для поиска и отображения. Может быть `null`. |
| `data` | object | Нет | Произвольный JSON-объект. Сервер принимает любые пары ключ-значение и не требует фиксированной структуры. При отсутствии поля возвращается `data: null`. |

> **Ключевое поведение:** `data` — гибкий контейнер: API не валидирует внутреннюю структуру и не отклоняет неожиданные поля. Это особенность демо-API.


### Примеры запросов

#### cURL

```bash
curl -X POST {{base_url}}/objects \
  -H "Content-Type: application/json" \
  -d '{
    "name": "new name",
    "data": {
      "anyKey": "любое значение",
      "anotherField": 123
    }
  }'
```

#### JSON: с данными

Запрос с `data`:

```jsonc
{
  "name": "new name",
  "data": {
    "anyKey": "любое значение"
  }
}
```

#### JSON: пустой запрос (минимальный кейс)
```json
{ }
```


## Коды ответов и поведение
|Код	|Статус	|Поведение API	|Что документировать для разработчика|
| --- | --- | --- | --- |
|200 |OK	|Успех	|Возвращает JSON с данными нового объекта |	
|400 |Bad request	|Ошибка в запросе	|Возвращает  "error": "Invalid request body" |	

## Формат успешного ответа (200 OK)

С данными:

```json
{
  "id": "ff808181a09d98f701a0c97c851d6f4a",
  "name": "new name",
  "createdAt": 1790086776093,
  "data": {
    "anyKey": "любое значение"
  }
}
```

Без `data` и `name`:
```json
{
    "id": "ff808181a09d98f701a12b569ca13d81",
    "name": null,
    "createdAt": 1791728458914,
    "data": null
}
```

## Структура ключевых полей
|Поле	|Тип	|Описание	|Ограничения / примечания|
| --- | --- | --- | --- |
|id|	string	|Уникальный идентификатор созданного объекта	|Генерируется  системой|
|name	|string/null|	Ярлык/имя объекта для поиска, фильтрации и отображения в списках |Как передано в запросе; может быть null|
|createdAt	|integer (Unix timestamp in milliseconds)	|Время создания объекта (в мс)|	UTC, Unix timestamp|
|data	|object/null|Произвольные данные объекта |Как передано в запросе; может быть null|

## Ограничения и особенности (демо-API)

- Статус-код для успешного создания — `200 OK` вместо ожидаемого `201 Created`. Это специфика демо-сервиса.
- Нет жёсткой схемы для data: любые ключи допустимы.
- Данные не сохраняются надолго: объекты могут удаляться при сбросе сервиса.
- Нет rate limiting и детальных кодов ошибок: большинство проблем с валидацией приводит к `400 Bad Request`.

## Связанные эндпоинты

- `GET /objects` — получить список объектов или конкретный объект по ID.
- `PUT /objects/{id}` — обновить объект.
- `DELETE /objects/{id}` — удалить объект.
