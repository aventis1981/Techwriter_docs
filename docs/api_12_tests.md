
## 	Тесты
|Кейс	| Позитивный/негативный	|Запрос	|Статус |Что проверяет| 
| --- | --- | --- | --- | --- |
|P1.1 | Позитивный |POST /objects с `{"name": "test"}` и без data |200 *(в реальном API должно быть 201)* |**Проверка контракта**: подтверждаем, что отсутствие поля data в запросе корректно отражается в ответе как data: null. Поле id обязательно присутствует.| 
|P1.2 | Позитивный|POST /objects с `{ "name": "test", "data": { "title": "x" } }`|200	| **Структура ответа:** проверяем, что объект, переданный в поле data, возвращается в ответе без искажений и остаётся объектом. Поле id присутствует. | 
|N1 |Негативный |POST /objects с пустым body |400 `Bad Request`	|**Валидация:** запрос без тела отклоняется, сервер возвращает error: "Request body is missing". Проверяем статус + сообщение.| 
|N2 | Негативный|POST /objects с невалидным body ("userId": string вместо number)  |400 `Bad Request`	|**Валидация типов:** Сервер отклоняет запрос из-за несоответствия типов/структуры и возвращает описание ошибки ("error": "Invalid request body"). Проверяем статус и наличие сообщения об ошибке.| 
|B1 |Граничный (позитивный) |POST /objects с пустым json {} |200| **Граничное значение:** валидный пустой JSON. Фиксируем поведение API: пустой объект принимается, сервер применяет значения по умолчанию (name: null, data: null). Поле id генерируется.|
